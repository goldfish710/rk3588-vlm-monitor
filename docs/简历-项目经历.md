**基于 RK3588 的板端多模态 VLM 智能家居监护终端**　　个人项目(独立完成)· C++/Linux · 2026.03–2026.09

板端部署 Qwen3-VL 大模型(RKLLM NPU),参与真实业务决策——跌倒复核、场景巡检、日志总结

**视频链路**(主/子双码流 30fps)

- 主码流:4K 采集 → RGA 缩放 → 1080p H.265 编码,全链路零拷贝(A/B 实测延迟降低 40%);MP4 循环录像,异常自动截存事发前后各 5 秒
- 子码流:640×480 送 AI——yolov8n-pose 跌倒候选检测(23ms/帧)

**语义理解**(VLM 参与业务决策)

- 两级跌倒复核:YOLO 候选 → VLM 看图复核 → MQTT 报警,端到端约 10s
- 周期巡检:每 60s VLM 生成场景摘要留"活动时间线",明火/浓烟即报警 + 语音提醒

**多模态交互**

- 语音:流式 ASR(RTF 0.087)→ VLM 对话 → TTS 逐句播报,首句 5.4s;呼救词触发视觉判定
- 远程操控(手机 4G 异网实测):网页客户端打开即用,快照 / 视觉问答 / 时间线回看 / 今日总结与异常回顾(VLM 汇总当天活动与事件) / 实时视频(MQTT 信令按需推流:板端零转码推 RTMP → 云端转 HLS → 多端同看、关流即停)

**系统优化**(硬件化 + NPU 调度)

- 硬件化:采集 → 编码 → AI 推理全走专用硬件(MPP/RGA/NPU),闲时 CPU 仅 ~2%
- NPU 调度:四类大模型业务共用单 NPU——优先级队列 + rkllm_abort 抢占 + 超时降级;实测抢占期间主码流 30fps 零影响、YOLO 仅降速 2 秒内恢复;满载温升 ~5°C 满频无降频
