# 4B 模型板端对比实测记录(Qwen3-VL-4B 官方 vs h3g 剪枝版)

> 测试日期:2026-09-12(板端 RK3588,RKNPU v0.9.8,3 核 NPU)
> 测试条件:同一张 demo.jpg(1024x640,宇航员月面喝啤酒图)、同一 prompt
> ("请描述这张图片的内容,包括人物、场景和可能发生的事情。")、
> max_new_tokens=2048、max_context_len=4096、共用同一 4B 视觉编码器(869MB)
> 原始日志:板端 /userdata/4b_bench/*.log;demo 已加 [BENCH] 计时补丁
> (prefill/generate/tok 数来自 SDK RKLLMPerfStat)

## 一、实测记录表

| 指标 | 官方 4B | h3g 剪枝版 | 备注 |
|---|---|---|---|
| 视觉编码耗时 | **2.40s**(3 次稳定) | **2.40s**(2 次稳定) | 视觉塔未剪,两者相同 ✓ |
| Prefill 耗时 | **2.87~2.89s**(220 tok) | **2.44~2.46s**(220 tok) | 剪枝版快 ~15% ✓ |
| 解码速度 | **4.70~4.77 tok/s** | **4.95 tok/s** | 剪枝版仅快 **+4.4%**,低于宣传 8~10% |
| 单次完整分析总耗时 | **~97s** | **~416s** | 剪枝版生成到 2048 上限才停(话痨),总耗时反而 4 倍 |
| 生成 token 数 | 446(自然结束) | 2047(触顶截断) | 剪枝版失去适时结束能力 |
| 模型加载内存 | ~4.7GB(page cache 增量) | ~4.4GB | free -m 实测;SDK perf.memory_usage_mb 字段不可信(负值,已弃用) |
| demo.jpg 描述质量 | 5/5(结构化、准确、诚实标注不确定项) | 1~2/5(前 3 段正常,随后幻觉漂移,编造 NASA 历史/虚构艺术家生平直到截断) | 详见表后描述摘录 |
| 连续运行稳定性 | **三连测全通过(两次实验)** | **第 2 次推理必挂板(3 次复现)**:板端冻结、adb 断连 | 致命伤 |

## 二、描述质量对比(原文摘录)

**官方 4B**(446 token 自然结束):分节描述(主要人物/场景/细节/可能发生的事情/
整体氛围),准确指出宇航员、啤酒、月球、地球、冷藏箱、梯子,并诚实标注
"啤酒瓶品牌模糊不清……无法完全确认"。**零幻觉,分寸感好。**

**h3g 剪枝版**(2047 token 触顶截断):前 3 段画面描述基本正常(宇航员/绿瓶/
月球/地球),随后**失控漂移**——开始编造"创作背景/历史背景/艺术家理查德·奥特曼
生平/NASA 阿波罗计划编年史"(虚构艺术家、虚构时间线、虚构奖项,长达 1700+ token
的连贯幻觉),直到 2048 上限被截断。

**质量结论**:剪 3 组注意力头后,模型在"围绕图像约束生成"上明显退化——
图像信息只锚定了开头 ~300 token,之后退化为无约束的自由联想(幻觉)。

## 二点七、h4g 双语恢复训练版(2026-09-12 晚,用户重训后复测)

测试条件同前;交互实测 7 轮 + 自动基准 3 轮。

| 指标 | 官方 4B | h3g(旧) | **h4g(新)** |
|---|---|---|---|

| prefill(220 tok) | 2.87~2.89s | 2.46s | **2.33s(-19%)** |
| decode | 4.70~4.77 tok/s | 4.95 | **5.63~5.74 tok/s(+19%)** |
| 生成行为 | 446 tok 自然停 | 2047 触顶 | **82 tok 自然停(简洁)** |
| 单次分析总耗时 | ~97s | ~416s | **~16.9s** |

**结论:h4g 全面胜出,已集成部署(默认模型),官方 4B 保留为切换基线。**
h3g 三宗罪(幻觉漂移/话痨/挂板)全部消除——恢复训练方向正确。

**模型切换方法**(板端 /AI/config.ini,改完重启 TLServer):
```ini
# h4g 剪枝版(当前默认):
rkllm_model=/userdata/models/qwen3-vl-4b-pruned-h4g-bilingual-merged_w8a8_rk3588.rkllm
# 官方 4B(回退基线):
rkllm_model=/userdata/models/qwen3-vl-4b-instruct_w8a8_rk3588.rkllm
```

注:大模型文件已全部迁至 /userdata/models/(根分区 14G 放不下多个 4B,迁出后根分区
恢复 4.8G 空闲);/AI/model/ 仅保留 2B 备份(.2b.bak)与 ASR/YOLO/piper 小模型。

## 三、结论与建议

1. **h3g 剪枝版不适合集成**:①提速仅 +4.4%(预期 8~10% 的一半)②话痨到触顶,
   实际单次分析耗时反增 4 倍 ③**连续第 2 次推理必挂板(3 次复现)**,工程不可用
2. **官方 4B 为集成首选**(用户已拍板暂停集成,待另行安排):
   - 板端 3 核 NPU 解码 4.74 tok/s、prefill 2.87s、视觉 2.40s
   - 质量高且稳定,三连测零故障
3. 若剪枝方向仍想推进,建议:h3g 的剪枝幅度/微调数据需回炉;或改用**蒸馏小模型**
   路线;集成前必须通过"连续 N 次推理稳定性"测试(本实验暴露的验收盲区)

## 四、实验过程备注(踩坑记录)

- SDK 的 demo 默认不打印 prefill/decode 指标(任务书描述有误),通过
  RKLLMPerfStat 补丁获得;其 memory_usage_mb 字段返回负值不可用,内存改用 free -m
- demo 交互式 stdin 协议:输入含 `<image>` 前缀的任意文本即触发多模态推理
- librkllmrt.so 依赖 libgomp.so.1,板端系统库缺失,需随包携带(TLServer /AI/lib 有现成)
- 板端连续推理时 adb/USB 曾三次断连,均为剪枝版第 2 次推理期间;官方版从未触发
