# RK 板端 AI 开发·服务器环境搭建指南

> 用途：在**新服务器**上搭建 RK 板端 AI 项目（交叉编译 + 模型转换 + 连板调试）的完整环境。
> 本指南基于 yolov8n-pose-monitor 项目在 RK3568→RK3588 两代平台上踩过的全部坑提炼，新项目可照此直接复用。
> 编写日期：2026-09-09

---

## 一、环境全景（先建立全局观）

一个 RK 板端 AI 项目需要四层环境，**版本一致性是生命线**：

```
┌─ PC 服务器 ─────────────────────────────────────┐
│ 1. conda 转换环境（rknn-toolkit2 + rkllm-toolkit） │  模型转换（x86，需要大内存）
│ 2. 交叉工具链（与板端镜像配套）                    │  编译板端二进制
│ 3. 第三方预编译库（live555/paho/kaldi 等）        │  交叉链接
│ 4. 连板工具（adb / rknn_server）                 │  连板推理调试
└───────────────────────────────────────────────┘
┌─ 开发板 ────────────────────────────────────────┐
│ 5. 系统镜像（与工具链同一 SDK 代际）               │
│ 6. NPU 三件套：驱动 / librknnrt.so / rknn_server  │  三者必须与转换工具同版本
│ 7. 部署依赖库（镜像缺的 .so 随包部署）              │
└───────────────────────────────────────────────┘
```

**铁律**：rknn-toolkit2（转换）、librknnrt（板端运行库）、NPU 驱动，三者版本必须一致（如 2.3.2 配套）。rknn 模型文件平台相关——3568 的 .rknn 不能跑 3588，换板必须重转。

## 二、PC 服务器环境

### 2.1 交叉工具链（按目标板选择，装到独立目录互不覆盖）

| 目标板 | 工具链 | 说明 |
|---|---|---|
| RK3568 | 正点 SDK 工具链（gcc 10.4，Linux 5.10 代际）| 路径约定 `/opt/atk-dlrk3568-5_10_sdk-toolchain` |
| RK3588 | 正点 6.1 版工具链 `atk-dlrk3588-toolchain-aarch64-buildroot-linux-gnu-x86_64_20260417-v1.0.run`（gcc 13.4）| 安装：`./xxx.run -y -d /home/yzy/atk-dlrk3588-toolchain` |

**教训**：
- 工具链必须与板端镜像同 SDK 代际（5.10 工具链编的程序在 6.1 镜像上库版本不匹配）
- 二进制 glibc 符号版本要 ≤ 板端镜像 glibc（`strings 二进制 | grep GLIBC_` 取最大版本，板端 `ldd --version` 对比）
- buildroot 工具链通常**无 OpenMP**（无 libgomp.spec/omp.h）——链接依赖 libgomp 的预编译库（如 librkllmrt）时加 `-Wl,--allow-shlib-undefined`，板端随包部署 libgomp.so.1
- 3588 的 6.1 工具链 sysroot 自带全套库（librga/librknnrt/librockchip_mpp/opencv4），优先用 sysroot；3568 时代则需外部编译 MPP/RGA

### 2.2 conda 转换环境（rknn-toolkit2）

```bash
# 2.3.2 用 python 3.12；官方 requirements 只写 onnx>=1.16.1 无上限（坑）
conda create -n py312-rknn232 python=3.12
conda activate py312-rknn232
pip install -r requirements_cp312-2.3.2.txt -i https://mirrors.aliyun.com/pypi/simple/
pip install rknn_toolkit2-2.3.2-cp312-cp312-linux_x86_64.whl
```

**必踩坑清单（2.3.2 + py3.12）**：
1. **onnx 必须降级 1.16.1**：onnx≥1.17 删除了 `onnx.mapping`，rknn load_onnx 直接崩。官方 requirements 写 `onnx>=1.16.1` 无上限是官方 bug
2. **pkg_resources 缺失**：py3.12 的 setuptools≥81 移除了它，rknn 包 import 报错 → conda-forge 装 `setuptools<81`
3. **torch 大包**：清华源缺 cp312 的 torch 2.4.0 → 官方源下 wheel 本地装（`pip install torch-xxx-cp312.whl`）
4. 磁盘预留 ≥30G（转换环境 + 缓存）；大模型转换（LLM/RKLLM 量化）需 32G+ 内存，不够就分到远程大内存机器

### 2.3 conda 转换环境（rkllm-toolkit，LLM 部署用）

```bash
conda create -n rkllm python=3.10
pip install rkllm_toolkit-1.3.0-*.whl
```
注意：RKLLM 的核数（npu_core_num）在**转换时烧进模型**，运行时改不了。

### 2.4 第三方预编译库（交叉链接用，与芯片无关可复用）

| 库 | 获取 | 备注 |
|---|---|---|
| live555 | 源码交叉编译 | RTSP 服务器 |
| paho.mqtt.c | 源码交叉编译 | MQTT 客户端；**板端镜像通常没有，libpaho-mqtt3c.so.1 随包部署** |
| fdk-aac | 源码交叉编译 | AAC 编码 |
| kaldi-native-fbank | rknn_model_zoo 预编译 .a | 注意需 `-no-pie`（其静态库未开 -fPIC） |
| OpenCV | 板端镜像自带（正点）或交叉编译 | 注意 3588 的 6.1 镜像带 opencv 4.5 |

### 2.5 连板调试

- adb（USB 或网络）：`adb shell` 进板端、`adb push/pull` 部署
- rknn_server（板端）+ rknn-toolkit lite2（PC）：PC 上 `init_runtime(target='rk3588')` 连板验证模型/分层性能（RKNN_LOG_LEVEL=4 分层日志只在连板模式下有）

## 三、板端环境

### 3.1 系统镜像

- RK3588：正点 **Linux 6.1** 镜像（AI 例程要求；出厂 5.10 需烧写 6.1）
- 烧录后验证：`cat /proc/version`、`dmesg | grep -i rknpu`（驱动版本）、`strings /usr/lib/librknnrt.so | grep version`

### 3.2 NPU 三件套版本核对（正点 3588 的 6.1 镜像免更新）

- rknpu 驱动 0.9.8（6.1 镜像自带，已最新）
- librknnrt.so 2.3.2 + rknn_server（镜像自带，已最新）
- **核对规则**：`strings /usr/lib/librknnrt.so | grep version` 与转换环境 rknn-toolkit2 版本一致；不一致才按官方文档 adb push 更新

### 3.3 部署清单模板（install 目录结构）

```
/app/                        # 板端运行目录
├── 主程序（RPATH=$ORIGIN/lib）
├── config.ini                # 全部可配置项
├── lib/                      # LD_LIBRARY_PATH=./lib
│   ├── librknnrt.so          # 与转换同版本
│   ├── libpaho-mqtt3c.so.1   # 镜像缺
│   ├── libgomp.so.1          # 镜像缺（librkllmrt 依赖）
│   └── （本地 TTS/其他运行库）
└── model/                    # rknn 模型 + 词表 + 大模型
```

**板端缺库排查法**：`readelf -d 二进制 | grep NEEDED` 逐个到板端 `ls /usr/lib/` 核对。

## 四、平台差异速查（RK3568 vs RK3588）

| 项 | RK3568 | RK3588 | 迁移动作 |
|---|---|---|---|
| 工具链 | 5.10 SDK（gcc 10.4）| 6.1 版（gcc 13.4）| 换工具链并重编 |
| NPU 核 | 单核 | 三核（rknn_set_core_mask 可配）| 多核对计算量小的网络可能反降速（实测 YOLO/zipformer 单核最优）|
| 声卡 | RK809（卡0）| ES8388（**卡1**）| config 设备号 + amixer 增益设置 |
| 摄像头节点 | /dev/video0/1 | **/dev/video62（主）+video63（子）** | 节点可配置化 |
| 镜像 | 5.10 | 6.1 | 烧录 + NPU 驱动核对 |
| RKLLM | 不支持 | 支持（VLM 本地化）| 模型 w8a8 转换 |

## 六、新项目注意事项（本项目教训的直接迁移）

1. **先测后优化**：性能优化前先做测量仪器（config 开关 A/B），"多核更快""零拷贝更好"等直觉都要实测验证（本项目实测：小网络多核变慢、流式 36 路 IO 不值得零拷贝）
2. **音频设备铁律**：所有 ALSA 句柄操作在采集线程内做（跨线程并发会段错误）；播放/采集共享时钟必须同采样率；ES8388 开机需 amixer 设置录音增益（重启恢复默认，写进启动脚本）
3. **流式 TTS 流水线**：VLM 边生成边逐句合成播放（双线程 + 背压队列），首句延迟从 ~14s 降到 ~3s；句粒度播放的句间停顿/句首吞字/末句卡死都是 ALSA 状态机问题（start_threshold/非阻塞 writei/drain 排空），参考 AudioPlayback 的最终实现
4. **模型平台性**：换板必重转模型；混合量化（关键点输出保 fp16）比全 INT8 稳
5. **版本一致性自查**：转换工具 / 板端 librknnrt / NPU 驱动三方版本一致是 90% 疑难杂症的答案
