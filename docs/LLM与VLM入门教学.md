## 第 1 章:LLM 是什么?——一个"预测下一个词"的机器

### 1.1 一句话定义

LLM(Large Language Model,大语言模型)本质是一个**根据前面所有文字预测下一个 token 的条件概率模型**:

```
P(下一个词 | 前面所有词)
```

你问它"马云是谁",它逐词生成:马 → 云 → 是 → 一位 → ... 每生成一个词,就把新词接上去,再预测下一个,直到输出结束符。这个过程叫**自回归生成(autoregressive)**——你在 zipformer 里写的贪心搜索就是这个模式:decoder 上下文只有 2 个 token,LLM 的"上下文"是几千到几万个 token,原理一样,规模不同。

### 1.2 和你在视觉课上学的东西,根本差异在哪

| | 你学过的视觉模型 | LLM |
|---|---|---|
| 输入 | 图像(连续像素) | 文本(离散 token 序列) |
| 任务 | 分类/检测/分割(固定类别) | **任意任务**(问答/翻译/写代码/聊天) |
| 训练信号 | 人工标注(几万~百万张) | **互联网全部文本**(几万亿 token,自监督) |
| 模型结构 | CNN(局部感受野) | **Transformer(全局注意力)** |
| "理解" | 模式匹配 | 涌现的推理/知识(规模大了才有) |

核心思想转变:**从"为每个任务训一个模型"到"一个模型完成所有任务"**。YOLO 只能检测 80 类,LLM 能做你临时想到的任何文字任务——因为它学会了"语言的规律"而不是"某个任务的规律"。

## 第 2 章:LLM 的内部结构(面试重点)

### 2.1 四个组件(从输入到输出)

```
文本 "你好" 
  → ① Tokenizer:切成 token 序列 [57668, 105] 
  → ② Embedding:每个 token 查表变成向量(如 4096 维)
  → ③ Transformer 堆叠(N 层,每层注意力+前馈网络):向量之间充分交互
  → ④ LM Head:最后一层向量 → 词表大小的概率分布 → 采样出下一个 token
```

**①Tokenizer 你已会**:你的 vocab.txt 就是 BPE(Byte Pair Encoding)词表——高频词单独成 token,罕见词拆成字/子词。LLM 词表更大(DeepSeek 约 12.8 万)。面试常问:"为什么中文 token 效率低?"——中文常用字多,同样一句话 token 数比英文多 1.5~2 倍,费钱。

**②Embedding**:和视觉里的 1×1 卷积升维/全连接查表一样,把离散 id 映射成稠密向量。数字 57668 本身没有语义("57 和 105 谁大"无意义),查表后才有。

**④LM Head**:一个"词表大小的分类头"——你在 YOLO 里写过 80 类 softmax,LLM 是十几万类的 softmax。你的 zipformer joiner 输出 6254 维 logits 做 argmax——**一模一样,只是这里叫"采样(sampling)"**(见 2.4)。

### 2.2 Transformer 注意力:整章最难、面试必问

CNN 的卷积是"局部看"(3×3 感受野逐层扩大),Transformer 的注意力是"**全局看**":每个词直接和所有词对话。

直觉版(无公式):

```
句子: "苹果 很 好吃"
问: 预测"好吃"后面是什么?模型需要知道重点在"苹果"上。

注意力做的事:对每个位置,计算"我应该多关注其他哪些位置"的权重。
"好吃"对"苹果"的注意力权重高(0.7),对"很"低(0.2)。

具体:每个 token 生成三个向量:
  Query(我要找什么) × Key(我有什么) → 相关度分数 → 加权求和 Value
```

这就是 **QKV 注意力**。多头 = 多组 QKV 并行(像 CNN 的多通道,每组关注不同关系:语法、指代、语义……)。

面试必背要点:
- **位置编码**:Transformer 没有循环结构,必须显式告诉模型词的顺序(加法或旋转位置编码 RoPE)
- **复杂度 O(n²)**:序列长 n,注意力矩阵 n×n——这就是"上下文窗口"为什么贵
- **Decoder-only**:现在的 LLM 只用 Transformer 的"解码器"半边(带因果掩码:预测第 i 个词时只能看 1~i-1,不能偷看未来)

### 2.3 规模是魔法:为什么"大"模型才聪明

| 规律 | 说明 |
|---|---|
| **Scaling Law(缩放定律)** | 模型越大、数据越多,能力可预测地变强——所以叫"大"模型 |
| **涌现能力** | 小模型不会的能力(推理/多步规划/工具使用),参数量过阈值后突然出现 |
| 参数量级 | GPT-2:15 亿 → GPT-3:1750 亿 → 现在主流:几十亿~上万亿 |

参考数字:你板上的 zipformer 约几千万参数,RK3568 都跑得吃力;DeepSeek v4-flash 是 **284B(MoE 总参数量)** 的巨无霸,在云端 GPU 集群上跑。这就是为什么你的板子只能"调用 API"而不是"本地跑 LLM"——算力和内存差 3~4 个数量级。

### 2.4 生成与采样参数(你 config 里的每个键)

你 config.ini 里的参数,含义:

- **temperature(温度)**:softmax 前把 logits 除以 T。T 小→分布尖锐→几乎总选最大概率词(确定、无聊);T 大→分布平坦→更多随机(活泼、可能胡说)。T=0 就是贪心(你 zipformer 用的就是贪心)
- **max_tokens**:输出长度上限,到限截断(你日志里见过 `finish_reason: "length"`)
- **top-p / top-k**:只在前 k 个或累计概率 p 的候选里采样,压住离谱词
- **stop 序列**:生成到某个词就停

你日志里的 `finish_reason: "stop"` 就是模型自己生成了结束符,自然停下。

## 第 3 章:LLM 是怎么训练出来的(三段论,面试必问)

### 3.1 阶段一:预训练(Pre-training)——"读完整个互联网"

任务超级简单:**预测下一个词**。把互联网几万亿 token 的文本,切成"前文→下一个词"的样本对,自监督训练。

- 不需要人工标注(这就是和视觉最大的区别!YOLO 要标框,LLM 用现成文本)
- 成本:数千 GPU × 数月,数千万美元
- 产出:**基座模型(Base Model)**——会"续写"但不会"对话"。你问它"1+1=?",它可能接着你的话往下编

### 3.2 阶段二:监督微调(SFT)——"教它对话格式"

人工写几万~几十万条**问答对**(问题,标准答案),让模型学会:问句之后应该输出答案而不是续写。数据量小、成本低(几块 GPU 几天)。

### 3.3 阶段三:RLHF/DPO——"让它说人话、别骂人"

RLHF(基于人类反馈的强化学习):模型生成多个回答 → 人类排序(哪个更好)→ 训一个"奖励模型"→ 用强化学习微调。近年多用更简单的 **DPO**(直接偏好优化,省掉奖励模型)。

产出的东西叫**对齐(alignment)**:礼貌、拒绝有害请求、承认不知道。"对齐税"= 对齐后模型能力略降但可用性大增——面试可以聊这个权衡。

## 第 4 章:推理优化(和你做的 RKNN 优化同源)

| 技术 | 原理 | 你的经验对应 |
|---|---|---|
| **KV Cache** | 生成第 n 个 token 时,前 n-1 个 token 的 K/V 不用重算,缓存复用 → 提速数倍 | 类似你的 zipformer encoder 流式状态缓存(36 张量回填!同一思想) |
| **量化**(INT8/INT4) | 权重从 FP16 压到 INT8/INT4,显存降 2~4 倍 | 你做过 RKNN int8 量化,连"conf 被毁"的坑都同源 |
| **流式输出** | 边生成边发(SSE) | 你写的 DeepSeek SSE 客户端 |
| **MoE** | 模型有多个"专家"子网,每个 token 只激活一部分 → 总参数大但算力省 | DeepSeek v4-flash 284B 但每次只激活约 20B |

## 第 5 章:VLM 多模态大模型——"给 LLM 装上眼睛"

### 5.1 核心难题:文字和图像是两个世界

LLM 只能处理 token 序列。图像是像素矩阵。怎么把图"说"给 LLM 听?

### 5.2 标准解法:视觉编码器 + 对齐 + LLM

```
图像 → ① ViT 视觉编码器 → ② 投影/对齐层 → 变成"视觉 token" → ③ 拼在文本 token 里 → LLM 正常生成
```

- **① ViT(Vision Transformer)**:把图像切成 16×16 的 patch,每个 patch 当作一个"词"送进 Transformer——你学 CNN 时如果有"图也能当序列处理"的疑问,VIT 就是这个答案。YOLO 的 backbone 近年也用类似的注意力结构
- **② 对齐是关键**:视觉向量空间和文本向量空间不一致,直接拼不行。两大流派:
  - **CLIP 对比学习**(图文匹配):4 亿图文对,训练"图与配文向量距离近、与无关文距离远"。产物是一个"能看懂图"的通用视觉编码器
  - **Q-Former(BLIP-2)**:一个可学习的"翻译器",把视觉特征压缩翻译成 LLM 爱听的"语言"
- **③ 交给 LLM**:LLM 本身不动(或轻微微调),让它对着拼进来的视觉 token 继续它的强项——推理和语言

### 5.3 训练流程(和纯 LLM 类似的三段)

预训练(图文对:描述图、OCR、grounding)→ 多模态 SFT(问答对:看图回答)→ 多模态 RLHF(人类排序)。

### 5.4 VLM vs YOLO:什么时候用谁(产品视角,面试常问)

| | YOLO(你熟的) | VLM |
|---|---|---|
| 定位 | 任务特定、快、便宜 | 通用、慢、贵 |
| 典型部署 | 端侧 NPU,30fps | 云端 GPU,秒级延迟 |
| 你的项目 | 跌倒检测(板端实时) | 将来可以:事件图送 VLM 描述现场、过滤误报 |

一个真实的工业界组合拳:**端侧 YOLO 粗筛(便宜、快)→ 云端 VLM 精确认(贵、慢但聪明)**。你的项目恰好就是这个架构的雏形——面试讲这个,格局就有了。

## 第 6 章:进阶概念速览(面试加分项)

- **上下文窗口**:模型一次能"看见"的 token 数。你项目 messages 历史上限 12 条就是这个概念的工程版;超长上下文靠 KV cache 压缩/稀疏注意力
- **RAG(检索增强生成)**:外挂知识库,检索相关文档拼进 prompt——解决"模型不知道私有知识"和"幻觉"。落地最多的大模型应用形态
- **Function Calling / Tool Use**:模型输出结构化 JSON 表示"我要调用哪个工具"——智能体(Agent)的基础
- **Agent(智能体)**:LLM 作为大脑,循环"思考→调用工具→观察结果→再思考",完成多步任务
- **幻觉(Hallucination)**:模型自信地编造事实。来源:预训练目标是"像人话"而非"说真话"。对策:RAG、提示词约束、让模型"不确定就说不知道"
- **推理模型(Reasoning Model)**:输出前先生成长篇思考过程(你亲眼见过的 reasoning_content!),在思考中试错、拆解,数学/代码能力大涨,代价是慢和贵。你已经在 config 里关过它——这个概念你比大多数初学者都懂
- **提示工程**:system prompt 设计(你的"你是居家养老陪伴助手,名字叫小安"就是)、few-shot 示例、CoT(思维链,让模型"一步步想")

## 第 7 章:端侧 LLM 现状(你的板子为什么只能调 API)

| 指标 | 你板上的 zipformer | 最小的可用对话 LLM | DeepSeek v4-flash |
|---|---|---|---|
| 参数量 | ~3 千万 | 5~30 亿(1.5B~3B) | 2840 亿(MoE,激活~200亿) |
| FP16 内存 | ~60MB | 3~6 GB | ~570 GB(无法单卡) |
| 你的 RK3568 | ✅ 能跑(RTF 0.12) | ❌ 内存 3.7GB 都不够 | ❌❌ |

端侧 LLM 的路径:INT4 量化(3B 模型压到 ~2GB)+ 手机旗舰芯片(骁龙/天玑的 NPU,几十 TOPS)。RK3568 的 1 TOPS NPU 和 3.7GB 内存离这个门槛差一个数量级——所以"端侧 ASR + 云端 LLM"对你这个硬件是唯一正确架构(你已经做到了,这个判断本身就是面试答案)。

## 第 8 章:面试高频问题速查(本专题)

1. **Transformer 的注意力机制讲一下?** → 2.2 的 QKV + 全局关注 + 位置编码 + 多头
2. **LLM 训练分几个阶段,各干什么?** → 预训练(下词预测自监督)/ SFT / RLHF 或 DPO
3. **为什么 LLM 会幻觉?怎么办?** → 训练目标是"像人话";RAG/约束提示/承认不知道
4. **量化对模型有什么影响?怎么做?** → 你 RKNN int8 的经验直接平移:精度损失在极端值分布上,PTQ/GPTQ/AWQ
5. **VLM 怎么把图像接进 LLM?** → ViT 编码 + CLIP/Q-Former 对齐 + 拼 token
6. **你的项目为什么用"端侧 ASR + 云端 LLM"架构?** → 算力/内存差 3~4 个数量级;端侧做感知,云端做认知,业界标准(参考第 7 章)
7. **温度参数是干什么的?** → 采样分布陡峭度;0=贪心,你 zipformer 用的就是贪心
8. **流式输出怎么实现?** → SSE;你写过 chunked 解分块 + `data:` 行解析的完整客户端
9. **KV Cache 是什么?为什么能加速?** → 生成时复用历史 token 的 K/V;类比你 zipformer 的 encoder 状态缓存
10. **MoE 是什么?** → 多专家网络,每 token 部分激活;DeepSeek 的核心架构
