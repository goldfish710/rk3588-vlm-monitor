## 1.1 类和对象:struct 里可以放函数了

### C 的问题

C 里数据和操作数据是分开的:

```c
// C 风格:结构体只管数据,函数在外面操作它
struct Config {
    int width;
    char path[256];
};
void config_init(struct Config* c) { memset(c, 0, sizeof(*c)); }
void config_print(struct Config* c) { printf("%d\n", c->width); }

// 使用
struct Config c;
config_init(&c);
config_print(&c);
```

问题:数据和函数散落各处,谁都能碰 Config 的内部;忘调 init 就出事。

### C++ 的解法:class/struct 把数据和函数捆在一起

```cpp
struct Config {
    int width;
    std::string path;

    void init() { width = 0; path.clear(); }      // 成员函数,直接访问成员
    void print() const { printf("%d\n", width); } // const:承诺不修改成员
};

Config c;      // 不需要 config_init,可以写构造函数自动初始化
c.init();
c.print();     // 点号调用,内部就是 &c 传给了隐藏的 this 指针
```

**本质**:成员函数就是 C 的函数指针+隐式传 this,语法糖而已。

### 项目实例:`config.h` 的 MainStreamConfig

```cpp
// server/TLServer/config.h
struct MainStreamConfig {
    int width = 1920;          // ← C++11:成员可以在声明处给默认值(C 不行)
    int height = 1080;
    std::string rtsp_path = "h265";   // ← std::string,见 1.3
    bool osd_fps_enable = true;
};
```

你以前写 C 时,struct 只有字段。这里每个字段带默认值——**定义即初始化**,永远不会出现"忘初始化导致野值"的 bug。这就是 C++ 比 C 安全的第一步。

## 1.2 构造函数与析构函数:自动初始化、自动清理

### C 的问题:两件最容易忘的事

```c
FILE* f = fopen("a.txt", "r");
// ... 中间如果提前 return,忘了 fclose(f) → 资源泄漏
free(ptr);  // 忘 free → 内存泄漏;free 两次 → 崩溃
```

### C++ 的解法:RAII 思想(Resource Acquisition Is Initialization)

**对象创建时自动执行构造函数,销毁时自动执行析构函数**——无论函数怎么退出(正常 return 还是中途 return),析构都保证执行。

```cpp
class FileReader {
public:
    FileReader(const char* path) { f_ = fopen(path, "r"); }   // 构造:获取资源
    ~FileReader() { if (f_) fclose(f_); }                     // 析构:释放资源
private:
    FILE* f_;
};

void func() {
    FileReader r("a.txt");
    if (条件) return;   // 提前退出?没关系,析构自动跑,文件自动关
}
```

这就是 RAII,现代 C++ 最重要的思想。**你在本项目见到的所有类(AudioCapture、AsrEngine、ChatEngine)都是它的实践:init 获取资源,析构/stop 释放资源。**

### 项目实例:AsrEngine 的模型上下文

```cpp
// server/cpp/asr_thread.h
struct RknnCtx {
    rknn_context ctx = 0;                              // 默认值
    std::vector<rknn_tensor_attr> input_attrs;         // vector 见 1.4
    std::vector<rknn_input> inputs;
};
```

注意它**没有显式析构函数**——因为成员都是"自己会清理"的类型(vector 会自动释放内存)。C++ 的规矩:**能用成员自动管理的,不要手写析构**。我们项目里 release_model() 里手动 free 的写法其实是 C 习惯的残留,教学上正好对比:

```cpp
// server/cpp/asr_thread.cpp  release_model()——C 风格手动管理
for (auto &in : c->inputs)
    if (in.buf) { free(in.buf); in.buf = NULL; }   // malloc/free 是 C 遗产
```

## 1.3 std::string:告别 char* 的噩梦

### C 的三宗罪

```c
char buf[64];
strcpy(buf, src);        // src 超过 64 字节 → 缓冲区溢出
strcat(buf, "拼接");     // 又可能溢出
if (strcmp(a, b) == 0)   // 忘写 ==0 就是反逻辑
```

### C++ 的 std::string

```cpp
std::string s = "你好";
s += "，世界";                    // 拼接,自动扩容,不可能溢出
if (s == "你好，世界") ...        // == 直接比较内容
size_t pos = s.find("世界");      // 查找子串
std::string sub = s.substr(0, 2); // 截取
printf("%s\n", s.c_str());        // 需要 C 接口时用 .c_str() 取 const char*
```

### 项目实例:项目里 string 的典型用法

```cpp
// server/cpp/chat_engine.cpp  stripWakeWord()
std::string s;
for (char ch : segment)            // ← 范围 for,遍历每个字符
    if (ch != ' ') s.push_back(ch);

// server/TLServer/config.cpp  load() 解析键值对
else if (key == "wake_word")       // string 直接 == 比较
    chat.wake_word = value;        // 赋值是"拷贝内容",不是拷贝指针!
```

**关键认知**:`std::string a = b;` 是**深拷贝**(两份独立内存),不是 C 的指针别名。所以项目里函数间传 string 从不担心悬垂指针。

## 1.4 std::vector:会自己长大的数组

### C 的动态数组之痛

```c
int* arr = malloc(n * sizeof(int));  // 要记 n
arr = realloc(arr, m * sizeof(int)); // 扩容要自己搬数据
free(arr);                            // 忘了就泄漏
```

### C++ 的 vector

```cpp
std::vector<int> v;
v.push_back(1);        // 自动扩容
v.push_back(2);
v.size();              // 永远知道元素个数,不用自己记
v[0];                  // 像数组一样用
v.erase(v.begin());    // 删除第一个
// 离开作用域自动释放全部内存
```

### 项目实例:音频块队列

```cpp
// server/TLServer/AudioCapture.h
struct AudioChunk {
    int64_t ts_ms;
    std::vector<uint8_t> data;   // 音频字节,长度随采样率变化,vector 正合适
};

// server/cpp/asr_thread.cpp  Resampler::feed()
buf_.insert(buf_.end(), in, in + n);   // 尾部批量插入
buf_.erase(buf_.begin(), buf_.begin() + consumed);  // 头部删除
```

vector 的 `data()` 返回底层连续内存指针,所以能把 vector 当 C 数组传给老接口:

```cpp
// server/cpp/chat_engine.cpp  写 TTS 音频文件
fwrite(wav.data(), 1, wav.size(), fp);   // wav.data() = 连续内存首地址
```

## 1.5 引用 &:没有空指针的"别名"

### C 的问题

```c
void set_val(int* p) { if (!p) return; *p = 10; }  // 总得防 NULL
set_val(&x);   // 调用侧要记得取地址
```

### C++ 的引用

```cpp
void set_val(int &r) { r = 10; }   // r 是 x 的别名,不可能是空
set_val(x);                        // 调用侧不用取地址
```

引用最常用在**函数参数**上:传大对象不想拷贝、又不想用指针。项目里到处是:

```cpp
// server/cpp/asr_thread.h
void setSegmentCallback(std::function<void(const std::string &segment)> cb);
//                                                     ↑ const 引用:
// 不拷贝 string(省内存),又不允许被修改

// server/TLServer/config.h
bool load(const std::string &path);   // 传参用引用
```

**对比记忆**:`T*` 可以空、可以改指向;`T&` 必须绑定、永不为空、绑定后不可改。函数参数能用引用就用引用。

## 1.6 两个容易混的运算符:-> vs . ,:: 

```cpp
// 指针用 ->,对象用 .(和 C 完全一样)
AsrEngine *e = new AsrEngine();
e->feedPcm(chunk);        // 指针
AsrEngine e2;
e2.feedPcm(chunk);        // 栈对象

// :: 是"作用域解析符":类名::成员,或者访问全局
std::thread t(&AsrEngine::asrLoop, this);   // AsrEngine 类的成员函数 asrLoop
std::cout << ...                            // std 命名空间里的 cout
::exit_flag                                 // 显式访问全局变量
```

## 一句话总结

C++ 的核心不是新语法,是**让编译器替你管理**:"数据+行为"打包成类、创建销毁自动调用、内存自动释放。先接受这个心智转变,后面的 lambda、线程、智能指针都是它的延伸。
